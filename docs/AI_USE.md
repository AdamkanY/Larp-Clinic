## 4. How we checked the AI's work

Facts from the repository:

- **Rules first.** The leakage rules, the label and the split were fixed in `CLAUDE.md` before the model code was
  written, so the AI could not choose features that leak.
- **Tests.** 41 offline tests check the feature function (leaky fields are ignored), the predictions, the chart
  helpers and every page in Streamlit's test runner. `tests/test_app.py` also checks that no colour is hard-coded
  outside `app/ui.py` and that every source file carries the AI header.
- **Pull requests.** Most work arrived on branches as pull requests (#2 to #20) before it was merged into `main`.
- **Rules fixed before results.** The promotion bar for model v2 (+0.005 test ROC-AUC) was set before v2 was trained;
  v2 missed it and was not used, even though its numbers were slightly better.
- **Checking a suggestion against the model.** SHAP was the first approach for per-trial explanations. It was tested
  and rejected because its values missed the model's own log-odds by up to 2.2 (docstring of `src/predict.py`).

## 5. Reflection: what worked, what did not, what we changed

Draft from the repository history. **[team]** Confirm, correct and add your own experience.

**What worked**

- Speed: data pipeline, model, five app pages and tests within about three days (2026-11-03 to 2026-11-05).
- Explicit rules in `CLAUDE.md` kept the AI consistent across many sessions and two accounts (one feature function,
  one colour palette, the leakage rules).
- Asking the AI for tests together with the code caught problems early (the page tests click through every page).

**What did not work**

- **Confident text that was too strong.** Several pull requests were needed only to make the app's wording honest
  ("app/honest-wording", "app/explain-honest"): the first drafts presented percentages as more exact than they are.
- **Wrong facts copied forward.** The deadline in `CLAUDE.md` said Dec 16; the course slides say the upload is due
  Dec 10. The AI repeated what it was told; nobody checked it against the slides until the review on 2026-11-10.
- **Plausible but wrong methods.** SHAP looked like the standard answer for explanations but did not match the model.
- **Many redesign rounds.** The look changed four times in two days (pull requests #11, #12, #16, #17). **[team]** Was
  that useful exploration or churn?
- **Gaps the tests did not cover.** A record with a null phase list crashed the search card code; found only when the
  offline fallback was written.
- **Understanding lags behind the code.** **[team]** Be honest here: which parts can each of you explain without the AI?

**How we adapted**

- After the first sessions: the `CLAUDE.md` guides, so every new session starts from the same rules.
- Every change to `app/` or `src/` must update the folder's `CLAUDE.md` in the same commit.
- Fixed decision rules before experiments (model v2).
- **[team]** anything else (for example: smaller tasks per prompt, reviewing every diff, asking for explanations).

**Conclusions for future projects** **[team]**

- Write down the rules and the facts (deadlines, grading criteria) first, and check them against the source.
- Treat every number and every claim the AI writes as a draft until someone has checked it.
- Keep a short prompt log from day one; reconstructing it at the end is hard.
