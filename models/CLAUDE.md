# models/

Saved trained models (`.joblib`) and their metrics. Not for: training code or data. Every model file needs a
matching metrics file recording ROC-AUC, PR-AUC, the split dates and the feature list.

Everything here is regenerated by `python src/train.py` (tune + fit + evaluate the app models, feature set v1),
`python src/train.py --features v2` (the `_v2` files) or, for the test-time outputs only, `python src/evaluate.py`.
Do not edit by hand. Load models through `src/predict.py` (`load_model`,
`score`, `percentile`), never with a hard-coded path.

| File | Contains | Produced by | Used by |
|---|---|---|---|
| `gbm.joblib` | **App model** (feature set v1, 29 features). `CalibratedClassifierCV(method='isotonic', cv=5)` around the tuned GBM pipeline, fitted on train; `predict_proba` averages the 5 calibrated fold copies | `src/train.py` | `src/predict.py` (`score`), `app/` |
| `gbm_uncalibrated.joblib` | The tuned GBM pipeline itself: ordinal-coded categoricals + `HistGradientBoostingClassifier(class_weight='balanced')`, native categorical splits. Kept for the before/after comparison, as the ablation reference and as the model `explain()` reads (smooth log-odds) | `src/train.py` | `src/evaluate.py`, `src/predict.py` (`explain`) |
| `gbm_v2.joblib`, `gbm_uncalibrated_v2.joblib` | Same protocol on feature set v2 (+ 9 condition-category features, 38 in all). Not the app model: see "v1 vs v2" below | `src/train.py --features v2` | comparison, report |
| `explain_reference.json` | The "typical training trial" for `explain()`: train median of every number and 0/1 flag, most common value of every category, over all 38 feature columns | `src/train.py` | `src/predict.py` (`explain`) |
| `baseline_lr.joblib` | sklearn Pipeline: impute/scale/one-hot + `LogisticRegression(class_weight='balanced')` (uncalibrated) | `src/train.py` | `src/evaluate.py`, `app/` (explanations) |
| `<model>_metrics.json` (one per `.joblib`) | Split dates and sizes, feature list, CV grid + best params, F1 threshold and OOF metrics (from out-of-fold train predictions), test ROC-AUC / PR-AUC / Brier, confusion matrix at that threshold, calibration bins, majority baseline, sklearn version. `gbm_metrics.json` adds `calibration` (test Brier before/after), `score_reference` and `ablations` | `src/train.py` (train/CV parts), `src/evaluate.py` (`test`, `majority_baseline`, `calibration.test_*`, `ablations`) | `app/`, report |
| `score_reference.npy` | Sorted out-of-fold calibrated scores of the 114,600 train trials (start 2008-2016); the reference for `percentile()`. `score_reference_v2.npy` is the same for `gbm_v2` | `src/train.py` | `src/predict.py` (`percentile`) |
| `calibration_before_after.png` | GBM calibration curve + prediction histogram on test, before vs after isotonic calibration | `src/evaluate.py` | report, video |
| `feature_importance.csv` | Permutation importance on test for `baseline_lr`, `gbm` and `gbm_v2`, one row per model x raw feature: mean/std drop in ROC-AUC and PR-AUC, `rank` by ROC-AUC drop | `src/evaluate.py` | `app/pages/2_Explain.py` (`gbm` rows), report |

## v1 vs v2: condition categories (2026-11-05)

v2 adds keyword multi-hot condition categories (`cond_oncology`, `cond_cardio`, `cond_neuro`, `cond_infectious`,
`cond_metabolic`, `cond_psych`, `cond_respiratory`, `cond_healthy`) and `n_condition_categories`. Same split, CV
folds, grid, calibration and threshold rule; the grid picked the same hyperparameters. Promotion rule set before
the run: replace the app model only if the calibrated GBM's test ROC-AUC improves by at least 0.005 and CV agrees.

| Model | Features | CV ROC-AUC (train) | OOF PR-AUC | Test ROC-AUC | Test PR-AUC | Test Brier |
|---|---|---|---|---|---|---|
| `gbm` (v1, app) | 29 | 0.710 ± 0.004 | 0.222 | 0.7102 | 0.2319 | 0.0974 |
| `gbm_v2` | 38 | 0.714 ± 0.003 | 0.228 | 0.7139 | 0.2396 | 0.0971 |
| Δ | +9 | +0.004 | +0.006 | **+0.0037** | +0.0077 | -0.0003 |

CV agrees in sign, but +0.0037 test ROC-AUC is below the bar, so `gbm.joblib` stays v1. PR-AUC gains more
(+0.008), mostly from oncology (21% terminated vs 11% overall). The logistic regression gained about as much
(test ROC-AUC 0.689 -> 0.692) in a run that was not kept. `predict.model_features` feeds each saved model its own
inputs, so v1 keeps working while `build_features` returns the 38 columns.

## Ablations: post-registration edits

The API returns each record's latest version, so features a sponsor can amend after the start might carry
post-start information. The GBM was refitted on train without them (same hyperparameters, uncalibrated, so the
reference is `gbm_uncalibrated`). Losing them costs under 0.01 ROC-AUC, so the model does not depend on them.

| Variant | Features | CV ROC-AUC (train) | Test ROC-AUC | Δ test ROC-AUC | Test PR-AUC |
|---|---|---|---|---|---|
| All features | 29 | 0.710 | 0.709 | – | 0.233 |
| Without `eligibility_text_len` | 28 | 0.703 | 0.701 | -0.008 | 0.229 |
| Without `n_primary_outcomes`, `n_secondary_outcomes` | 27 | 0.707 | 0.708 | -0.001 | 0.231 |
| Without all three | 26 | 0.701 | 0.701 | -0.009 | 0.229 |

## Notes

- `score()` returns the **calibrated** probability. On train (out-of-fold) the mean score equals the terminated rate
  (0.111). On test it is 0.099 vs an observed 0.117: 2017-2019 trials look lower-risk on paper (more phase-NA,
  behavioural and healthy-volunteer studies) yet terminated slightly more often. Expect the same downward bias
  for recent and ongoing trials.
- `baseline_lr` and `gbm_uncalibrated` probabilities are inflated by `class_weight='balanced'`; use them for
  ranking only.
- `.joblib` files only load reliably with the sklearn version in `sklearn_version` of the metrics JSON
  (`requirements.txt` pins it). Retrain if you change the pin.
