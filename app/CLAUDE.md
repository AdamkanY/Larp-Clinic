# app/

The Streamlit app (entry point plus pages). Not for: model training, data cleaning or feature logic
(import them from `src/`). Relative paths only; the app must run on Streamlit Community Cloud.

Run with `streamlit run app/Home.py` from the repo root. Pages add the repo root to `sys.path` so they can
import `src.*`. Pages must not call `st.set_page_config` (`Home.py` does it once for all) and start with
`require_router(...)` from `ui.py`.

| File | Contains / does | Produced by | Used by |
|---|---|---|---|
| `Home.py` | Entry point. Sets the page config once, builds the sidebar with `st.navigation` (Home, Find a trial, Check your own trial, Explore the data, How the model works) and holds the landing page: gradient banner, four cards, colour legend with a plain note on how to read a result. Sets `via_router` so pages know they were opened through it | Matteo | `streamlit run app/Home.py` |
| `ui.py` | Shared look: one stylesheet (content width, sidebar, captions, cards, chips incl. risk colours, metric tiles, `panel_*` containers whose columns wrap, a sticky `sticky_*` strip, risk card colours) plus `hero`, `page_header(title, subtitle)`, `chip(text, tone)`, `esc(text)` (HTML escaping) and `require_router(page)`: a page opened directly (browser refresh, bookmark) is sent through `Home.py` and comes back, so it keeps the navigation and wide layout. Cards are `st.container(key="card_...")` styled by key. Theme colours live in `.streamlit/config.toml`. Restart the server after editing it (Streamlit does not reload imported modules) | Matteo | all pages |
| `risk_gauge.py` | Shared risk display: `risk_tone(risk)` (green below the median trial, yellow up to the riskiest 10%, red above, by rank in `models/score_reference.npy`), `risk_card(risk, delta, compact)` (big coloured card, or a one-line strip), `risk_chip(risk)` (small label for result lists), `risk_bar(risk)` with `bar_caption()`, `estimate_caption(risk, ongoing)` (honest reading; quotes the under-prediction gap from `models/gbm_metrics.json`). No dial: a 0-40% dial looked like "50%" | Matteo | `pages/1_Search.py`, `pages/5_Check_Your_Trial.py` |
| `pages/1_Search.py` | One search box with example pills, phase and sponsor filters, "Clear all"; ongoing interventional trials as cards (title, risk chip, phase and status chips, sponsor, "See details"), 10 at a time. The search results already hold the full records, so each card is scored directly (`risk_for`, cached per trial and record version; observational records get no score). "See details" opens a page with the coloured risk card, comparison bar and key design facts. Plain names from `src/labels.py`; errors and empty results come with a next step. Model loaded once with `st.cache_resource` | Matteo | users |
| `pages/2_Explain.py` | "In short" box, then four tabs: what is predicted (label definition and what is not in the data), how good it is (test ROC-AUC / PR-AUC / Brier vs guessing, plain-words examples, ranking quality per phase), what matters most (top 12 factors from `models/feature_importance.csv`, coloured by direction measured on the training trials), can you trust it (predicted vs real per risk group and per year). Numbers come from `models/gbm_metrics.json`; the phase, year and direction tables score or read `data/processed/trials.parquet` (cached). Each part shows a message if its file is missing | Matteo | users |
| `pages/2_Explore.py` | Charts of the historical trials: filters on the page (phase, sponsor, start year, condition keyword, "Clear filters"), three key numbers, share stopped early by phase / sponsor / blinding / allocation (with the average as a dashed line and the highest and lowest group named), by start year, the 15 most common conditions and by length of the eligibility criteria (grouped bars instead of the old log-scale box plot), and a searchable trial table linking to clinicaltrials.gov. Loads `trials.parquet` once via `st.cache_data`; charts come from `src/viz.py`. No model code | Adam / Matteo | users |
| `pages/4_Game.py` (expected) | Guess which of two trials was terminated, scored vs the model | Raphael | users |
| `pages/5_Check_Your_Trial.py` | Form to enter a trial design from scratch (grouped panels, plain names and help texts, "Reset to the example trial"); a sticky strip at the top shows the live risk while the form is edited, below it the comparison bar and "What would lower the risk?" (best single change per setting; nonsensical ones such as phase -> "No phase" are skipped). The form fills exactly `FEATURE_COLUMNS`; model via `st.cache_resource` | Matteo | users |
