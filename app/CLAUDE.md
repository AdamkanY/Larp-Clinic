# app/

The Streamlit app (entry point plus pages). Not for: model training, data cleaning or feature logic
(import them from `src/`). Relative paths only; the app must run on Streamlit Community Cloud.

Run with `streamlit run app/Home.py` from the repo root. Pages add the repo root to `sys.path` so they can
import `src.*`. Pages must not call `st.set_page_config` (`Home.py` does it once for all) and start with
`require_router(...)` from `ui.py`.

| File | Contains / does | Produced by | Used by |
|---|---|---|---|
| `Home.py` | Entry point. Sets the page config once, builds the navigation with `st.navigation(position="top")` (Home, Find a trial, Check your own trial, Explore the data, How the model works; Streamlit folds it into a sidebar on a phone) and holds the landing page as full-width ink and paper bands: a hero with one giant statistic (share stopped early, from `load_metrics()` in `src/predict.py`) above a 100-tick scale, one band per page (headline, one sentence, one action; Explore and Explain carry a big number from the same file), then the colour legend with the plain note on how to read a result. Sets `via_router` so pages know they were opened through it | Matteo | `streamlit run app/Home.py` |
| `ui.py` | Python side of the look: `stylesheet()` (reads `style.css` once), `inject_css`, `hero(...)`, `band_copy(...)`, `tick_scale(marked, label)` (the signature 100-tick scale), `page_header(title, subtitle)` (dark band that opens every page but Home), `chip(text, tone)`, `esc(text)` (HTML escaping) and `require_router(page)`: a page opened directly (browser refresh, bookmark) is sent through `Home.py` and comes back, so it keeps the navigation and wide layout. Cards and panels are `st.container(key="card_...")` / `key="panel_..."` styled by key; landing bands are `key="band_hero"`, `band_ink_*`, `band_paper_*`. Restart the server after editing `ui.py` or `style.css` (Streamlit does not reload imported modules) | Matteo | all pages |
| `style.css` | The whole stylesheet: design tokens as CSS variables (ink, paper, one pink accent used only for "this trial" and the main action, risk colours, corner and spacing scales), frosted top navigation, full-bleed bands with grain and radar rings, buttons, chips, inputs, metric tiles, risk card and sticky strip, one page-load reveal (off under `prefers-reduced-motion`). Fonts come from `.streamlit/config.toml` | Matteo | `ui.py` |
| `static/fonts/` | Self-hosted variable fonts (Bricolage Grotesque, IBM Plex Sans; OFL licence), served at `/app/static/fonts/...` because `enableStaticServing` is on | Google Fonts | `.streamlit/config.toml` |
| `risk_gauge.py` | Shared risk display: `risk_tone(risk)` (green below the median trial, yellow up to the riskiest 10%, red above, by rank in `models/score_reference.npy`), `risk_card(risk, delta, compact)` (big card with a light numeral and a coloured label, or an ink strip with a 100-tick meter and one pink tick for this trial), `risk_chip(risk)` (small label for result lists), `risk_bar(risk)` (pale bands, pink line for this trial) with `bar_caption()`, `estimate_caption(risk, ongoing)` (honest reading; quotes the under-prediction gap from `load_metrics()`). No dial: a 0-40% dial looked like "50%" | Matteo | `pages/1_Search.py`, `pages/5_Check_Your_Trial.py` |
| `pages/1_Search.py` | One search box with example pills, phase and sponsor filters, "Clear all"; ongoing interventional trials as cards (title, risk chip, phase and status chips, sponsor, "See details"), 10 at a time. The search results already hold the full records, so each card is scored directly (`risk_for`, cached per trial and record version; observational records get no score). "See details" opens a page with the coloured risk card, comparison bar and key design facts. Plain names from `src/labels.py`; errors and empty results come with a next step. Model from `get_model()` in `src/predict.py` (loaded once per server) | Matteo | users |
| `pages/2_Explain.py` | "In short" box, then four tabs: what is predicted (label definition and what is not in the data), how good it is (test ROC-AUC / PR-AUC / Brier vs guessing, plain-words examples, ranking quality per phase), what matters most (top 12 factors from `models/feature_importance.csv`, coloured by direction measured on the training trials), can you trust it (predicted vs real per risk group and per year). Numbers come from `models/gbm_metrics.json` through `load_metrics()` (`src/predict.py`); the phase, year and direction tables score or read `data/processed/trials.parquet` (cached). Each part shows a message if its file is missing | Matteo | users |
| `pages/2_Explore.py` | Charts of the historical trials: filters on the page (phase, sponsor, start year, condition keyword, "Clear filters"), three key numbers, share stopped early by phase / sponsor / blinding / allocation (with the average as a dashed line and the highest and lowest group named), by start year, the 15 most common conditions and by length of the eligibility criteria (grouped bars instead of the old log-scale box plot), and a searchable trial table linking to clinicaltrials.gov. Loads `trials.parquet` once via `st.cache_data`; charts come from `src/viz.py`. No model code | Adam / Matteo | users |
| `pages/4_Game.py` (expected) | Guess which of two trials was terminated, scored vs the model | Raphael | users |
| `pages/5_Check_Your_Trial.py` | Form to enter a trial design from scratch (grouped panels, plain names and help texts, "Reset to the example trial"); a sticky strip at the top shows the live risk while the form is edited, below it the comparison bar and "What would lower the risk?" (best single change per setting; nonsensical ones such as phase -> "No phase" are skipped). The form fills exactly `FEATURE_COLUMNS`; model from `get_model()` in `src/predict.py` | Matteo | users |
