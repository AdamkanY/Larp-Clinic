# app/

The Streamlit app (entry point plus pages). Not for: model training, data cleaning or feature logic
(import them from `src/`). Relative paths only; the app must run on Streamlit Community Cloud.

Run with `streamlit run app/Home.py` from the repo root. Pages add the repo root to `sys.path` so they can
import `src.*`. Pages must not call `st.set_page_config` (`Home.py` does it once for all) and start with
`require_router(...)` from `ui.py`.

Colours come only from `PALETTE` in `ui.py` (no hex or rgba values in pages, `risk_gauge.py`, `style.css` or
`src/viz.py`; `tests/test_app.py` checks this). Show every chart with `ui.chart(fig)`, which applies the Plotly template.
Model numbers come only from `src.predict` (`score`, `score_frame`, `percentile`, `explain`), names only from `src/labels.py`.

| File | Contains / does | Produced by | Used by |

| `Home.py` | Entry point. Sets the page config once and holds `PAGES`, the one list of the five pages (title, file, sentence, action) in the order people use them: Find a trial, Check your own trial, Explore the data, How the model works, Play the game. `st.navigation(position="top")` and the landing-page bands both come from it, so navigation, Home cards and browser-tab titles cannot drift apart (Streamlit folds the navigation into a sidebar on a phone). The landing page is full-width bands: an ink hero with one giant statistic (share stopped early, read from `models/gbm_metrics.json`) above a 100-tick scale, then the "Who it is for" band (`AUDIENCES`: sponsors and study designers, investors and analysts, each with the decision it supports and a link to its page, plus `NOVELTY`, what the app adds to published models; its title uses `band-title small` so the Home test still lists only page bands), then one band per page alternating paper / ink (Explore and How the model works carry a big number from the same file), then the colour legend with the plain note on how to read a result. Sets `via_router` so pages know they were opened through it | Matteo | `streamlit run app/Home.py` |
| `ui.py` | The look in Python. **`PALETTE`: the only place colours are defined** (ink, paper, accent, risk tones, chart series). `css_variables()` turns it into CSS variables that `stylesheet()` puts in front of `style.css`; `plotly_template()` builds the "trial_radar" Plotly template from it (including the heatmap colour scale: paper to the pale yellow band to the "up" orange), registered as the Plotly default on import; `chart(fig, key)` shows a figure with that template (`theme=None`, and font and backgrounds copied onto the layout because Streamlit's frontend otherwise fills them from its own theme). Every page shows charts through `chart`, never `st.plotly_chart`. Also `alpha(colour, opacity)`, `inject_css`, `hero(...)`, `band_copy(...)`, `tick_scale(marked, label)`, `page_header(title, subtitle)` (dark band that opens every page but Home; its title equals the navigation title), `chip(text, tone)`, `esc(text)` and `require_router(page)`: a page opened directly (browser refresh, bookmark) is sent through `Home.py` and comes back. Cards and panels are `st.container(key="card_...")` / `key="panel_..."` styled by key; landing bands are `key="band_hero"`, `band_ink_*`, `band_paper_*`. Restart the server after editing `ui.py` or `style.css` (Streamlit does not reload imported modules) | Matteo | all pages, `risk_gauge.py` |
| `style.css` | The whole stylesheet, with no colour values of its own: it uses the `PALETTE` variables (`var(--ink)`, `var(--low-tint)`, ...) and `color-mix()` for transparent tints. Non-colour tokens (corner and spacing scales, fonts), frosted top navigation, full-bleed bands with grain and radar rings (the "who" and "read" bands on the lighter paper with hairlines), buttons, chips, inputs, metric tiles, risk card and sticky strip, one page-load reveal (off under `prefers-reduced-motion`). Fonts come from `.streamlit/config.toml` | Matteo | `ui.py` |

| `risk_gauge.py` | Shared risk display: `risk_tone(risk)` (green below the median trial, yellow up to the riskiest 10%, red above, by rank in `models/score_reference.npy`), `risk_card(risk, delta, compact)` (big card with a light numeral and a coloured label, or an ink strip with a 100-tick meter and one pink tick for this trial), `risk_chip(risk)` (small label for result lists), `risk_bar(risk)` (pale bands, pink line for this trial) with `bar_caption()`, `estimate_caption(risk, ongoing)` (honest reading; quotes the under-prediction gap from `models/gbm_metrics.json`), `drivers_chart(drivers)` + `drivers_caption()` ("What pushes this trial's risk up / down": the bars from `src.predict.explain`, `PALETTE` up / down colours, the same as the model page). No dial: a 0-40% dial looked like "50%" | Matteo / Adam | `pages/1_Find_a_Trial.py`, `pages/2_Check_Your_Trial.py` |
| `pages/1_Find_a_Trial.py` | **Find a trial.** One search box with example pills, phase and sponsor filters, "Clear all"; ongoing interventional trials (recruiting, not yet recruiting, active not recruiting, enrolling by invitation: `api_client.ONGOING`) as cards (title, risk chip, phase and status chips, sponsor, "See details"), 10 at a time. The search results already hold the full records, so each card is scored directly (`risk_for`, cached per trial and record version; observational records get no score). "See details" opens a page with the coloured risk card, comparison bar, the drivers chart (`drivers_for`, cached like `risk_for`) and key design facts. **Offline fallback:** if the API cannot be reached, the page searches the saved snapshot (`api_client.search_examples`, `data/examples/ongoing_trials.json`) under a warning with its download date; without a snapshot it shows the error and "Try again" as before. Plain names from `src/labels.py`; errors and empty results come with a next step. Model loaded once with `st.cache_resource` | Matteo | users |
| `pages/2_Check_Your_Trial.py` | **Check your own trial.** Form to enter a trial design from scratch (grouped panels, plain names and help texts, a conditions text box that names the recognised condition areas, "Reset to the example trial"); a sticky strip at the top shows the live risk while the form is edited, below it the comparison bar, the drivers chart and "What would lower the risk?" The form returns a design dict that goes through `src.features.features_from_design`, the same rules as real records; if the saved model wants inputs the form does not give, a plain message replaces the result. Model via `st.cache_resource` | Matteo / Adam | users |
| `pages/3_Explore_Data.py` | **Explore the data.** Charts of the historical trials: filters on the page (phase, sponsor, start year, condition keyword, "Clear filters"), three key numbers, share stopped early by phase / sponsor / blinding / allocation (with the average as a dashed line and the highest and lowest group named), a heatmap of two traits at once (`viz.rate_heatmap`; a segmented control picks phase x sponsor, phase x blinding or sponsor x allocation; thin cells stay empty), by start year, the 15 most common conditions and by length of the eligibility criteria (grouped bars instead of the old log-scale box plot), and a searchable trial table linking to clinicaltrials.gov. Loads `trials.parquet` once via `st.cache_data`; charts come from `src/viz.py` and are shown through `ui.chart`. No model code | Adam / Matteo | users |
| `pages/4_How_the_Model_Works.py` | **How the model works.** "In short" box, then a plain-English "How to read a risk score" box (what the percentage, the colour and the rank mean; it runs low; red is not a verdict; with the colour legend), then five tabs: what is predicted (label definition and what is not in the data), how good it is (test ROC-AUC / PR-AUC / Brier vs guessing, plain-words examples, a review-budget slider `gain_share` with the cumulative gain curve `gain_chart` from `viz.gain_curve`, half-violins of the predicted risk for completed vs stopped trials `score_violin`, ranking quality per phase), what matters most (top 12 factors from `models/feature_importance.csv`, named through `src/labels.py`, coloured by direction on the training trials), can you trust it (predicted vs real per risk group, a calibration plot of the test trials before vs after isotonic calibration, and per year, with the test-year tilt explained: only ended trials are in the data, so recent start years lean towards stopped ones), versions and checks (v1 vs v2 table from `gbm_metrics.json` / `gbm_v2_metrics.json` with the +0.005 promotion bar, and the ablation table from `gbm_metrics.json["ablations"]`). Test trials are scored with `src.predict.score_frame` (app model, and the uncalibrated GBM for the "before" curve; cached). Each part shows a message if its file is missing | Matteo / Adam | users |
| `pages/5_Game.py` | **Play the game** ("guess the stopped trial"): 10 rounds, each a TERMINATED and a COMPLETED trial of the same phase from the test split (start 2017-2019), shown as two cards in random order (title, conditions, phase, sponsor, blinding, allocation, arms, healthy volunteers, eligible ages; the outcome stays hidden until the guess). The user clicks "Trial A/B was stopped early"; the reveal shows the true answer, the model's pick (higher calibrated score) and a clinicaltrials.gov link per trial. Score you vs model lives in `st.session_state` (`game_rounds`, `game_round`, `game_picks`, `game_revealed`); the end shows a scoreboard, a per-round table and "Play again". A line shows the model's pairwise accuracy on a fixed 2,000-pair sample (`st.cache_data`, seed 0; ties count half). Logic in `src/game.py`; trials load once via `st.cache_resource` | Raphael | users |
