# src/

Reusable Python for data fetching, feature building, model training and the ClinicalTrials.gov API client.
Not for: Streamlit code (`app/`), exploration (`notebooks/`), data files or saved models.
Must not import from `app/` or `notebooks/`. Rules in the root `CLAUDE.md` (label, leakage, date split) apply to
everything here.

Pipeline: `python src/fetch_data.py`, then `python src/build_dataset.py`, then `python src/train.py`
(tunes, fits, saves and evaluates the app models on feature set v1; `python src/train.py --features v2` trains the
condition-category GBM as `gbm_v2` next to them; `python src/horse_race.py` then races six models on the same
time-ordered folds and writes `models/horse_race.json`; `python src/evaluate.py` re-runs only the test evaluation).
`python src/build_dataset.py --backfill` adds new condition features to the existing parquet without raw pages.

| File | Contains / does | Produced by | Used by |
|---|---|---|---|
| `fetch_data.py` | Downloads all INTERVENTIONAL COMPLETED/TERMINATED studies from the API v2 into `data/raw/pages/` (resumable, retry/backoff, progress; projection also fetches `BriefTitle`, `LeadSponsorName` for display) | Simon | `build_dataset.py` |
| `features.py` | `build_features(study_json) -> dict`: the single feature function (design-time fields only) plus column lists. Absent lists count as 0; missing max age = 120 with `has_max_age` flag; no `start_year`/`fda_regulated_*` features. `condition_features(conditions)`: keyword multi-hot `cond_oncology` / `cardio` / `neuro` / `infectious` / `metabolic` / `psych` / `respiratory` / `healthy` + `n_condition_categories` (patterns in `CONDITION_KEYWORDS`, matched at word starts; `CONDITION_FEATURES` lists the columns). `study_from_design(design)` / `features_from_design(design)`: a design typed into a form -> minimal API record -> `build_features`, so the Check page uses the training rules instead of a copy. `FEATURE_COLUMNS` = every feature column (38); which ones a model uses is `FEATURE_SETS` in `train.py`. `DISPLAY_COLS` = app-only columns (title, conditions text, sponsor name, phase label), never model inputs | Simon / Adam | `build_dataset.py`, `train.py`, `app/` |
| `build_dataset.py` | Runs `build_features` over raw pages, applies label and 2008-2019 window, adds `split`, writes `data/processed/trials.parquet`, prints counts and the terminated rate per condition category. `--backfill` recomputes the condition features from the stored `conditions` text (split on `"; "`) instead | Simon | `train.py`, app visuals |
| `viz.py` | Explore-page helpers: `load_trials` (adds `start_year`, `outcome`, `eligibility_group`; turns codes into plain names through `labels.py`; missing values become "Not stated"), `filter_trials`, `rate_by`, `extremes` (highest/lowest group in words), `top_conditions`, Plotly figure builders (`rate_bar`, `rate_over_time`, `conditions_bar` (takes ready-made `stats`, e.g. from SQL), `eligibility_stats`), `rate_matrix` + `rate_heatmap` (share stopped early for every combination of two traits; cells under `MIN_GROUP_N` blank, empty rows/columns dropped, None if nothing is readable), `condition_treemap`, `condition_bubbles` (both take ready-made `stats` like `conditions_bar`), `trials_per_year_area` and `flow_sankey` (the four extra views of the Explore page; groups under `MIN_GROUP_N` dropped, None if nothing is left; `flow_sankey` derives the outcome from `label`), `gain_curve` (cumulative gain: share of stopped trials found when the riskiest x% are reviewed; used by the model page) and `trials_table`. No colours or fonts: the figures take the app's Plotly template, which `app/ui.py` registers as the default (src must not import app). Pure pandas/Plotly, no Streamlit, no model | Adam / Matteo | `app/pages/3_Explore_Data.py`, `app/pages/4_How_the_Model_Works.py` (`gain_curve`) |
| `train.py` | Loads `trials.parquet` and checks label / window / split rules, sorts the train split by start date (`load_split`), builds the LR and GBM Pipelines, tunes each by **time-ordered CV** on train (`make_cv` = `TimeSeriesSplit(5)`, an expanding window: train on earlier trials, validate on the next block; refit on PR-AUC; every grid cell keeps its fold spread), wraps the tuned GBM in `CalibratedClassifierCV(method='isotonic')` with 5 shuffled stratified folds (calibration tunes nothing) fitted on train, picks each model's F1-max threshold on the out-of-fold predictions of the validation blocks (`time_ordered_predictions`; the first block is only ever trained on), saves `models/<name>.joblib` + `<name>_metrics.json`, `score_reference.npy` (OOF calibrated scores) and `explain_reference.json` (typical train trial), then calls `evaluate.evaluate_saved`. `FEATURE_SETS` = `v1` (29 original features, `APP_FEATURE_SET`) and `v2` (+ condition categories); `--features v2` trains only the GBM and saves it with a `_v2` suffix. `build_gbm_pipeline(drop=..., features=...)` serves the ablations | Adam | CLI, `evaluate.py` |
| `horse_race.py` | The model race of DSF deck 16: baseline (`DummyClassifier`), decision tree, random forest and k-nearest neighbours (min-max scaling, odd k, as in the CS course) are grid-searched on the same `make_cv` folds with a one-hot `Pipeline` (defaults always the first cell); logistic regression and GBM are read from the grids `train.py` stored. Tuned = best PR-AUC cell. `verdict` names the winner and checks whether its lead beats the fold spread (else the simplest tied model is named). Writes `models/horse_race.json`; never touches the test split | Claude | CLI, `app/pages/4_How_the_Model_Works.py` |
| `database.py` | The SQLite database behind the Explore page (CS course chapter 3). `build_database` / `ensure_database` write `data/processed/trials.db` from `viz.load_trials` (built on first use or when the parquet is newer; not in git): table `trials` (primary key `nct_id`) and table `trial_conditions` (one row per trial and condition, foreign key `nct_id`: the `"A; B"` cell split for the first normal form). `where_clause` turns the page's filters into a WHERE part with `?` parameters (user text never enters the SQL; `instr` so `%` and `_` are plain characters). `TrialDatabase(db_path, phases, sponsor_classes, year_range, condition_kw)` runs read-only `pd.read_sql` queries and logs them for the page: `options` (filter choices), `summary` (COUNT, AVG), `trials` (SELECT ... WHERE), `rate_by` (GROUP BY one of `GROUP_COLUMNS` only) and `top_conditions` (JOIN + GROUP BY + ORDER BY + LIMIT). `python src/database.py` rebuilds and prints examples | Claude | `app/pages/3_Explore_Data.py` |
| `open_trials.py` | The check behind the test-year tilt: `count(year, status)` asks the API how many interventional trials of a start year have a status today, `fetch_counts` does it for 2008-2019 and every status (`python src/open_trials.py` rewrites `data/processed/open_trials_by_year.csv`), `load_counts` reads the saved file, `tilt_table(counts, predicted)` gives per year the share still running, the share with unknown status, the rate among ended trials, the lowest possible final rate (every running trial completes) and both gaps to the model's average prediction | Simon / Claude | `app/pages/4_How_the_Model_Works.py` |
| `evaluate.py` | The only code that scores the test split: test ROC-AUC / PR-AUC / Brier, confusion matrix at the stored threshold, majority baseline, calibration before/after (JSON + plot), permutation importance CSV (a `_v2` run only replaces its own rows), LR coefficients, and the GBM feature ablations (refit on train without post-registration-editable features, scored once on test). Each model is fed its own input columns. Matplotlib is imported at the top (only this file and `train.py` need it, the app does not import them) | Adam / Dominic | `train.py`, CLI, `app/` |
| `predict.py` | `load_model(path='models/gbm.joblib')`, `score(features: dict) -> float` (**calibrated** P(TERMINATED)), `score_frame(records) -> array` (same, one call for a whole table; the How the model works page and the game use it), `percentile(prob) -> float` (0-100: share of training trials with a lower out-of-fold score), `reference_size()`, `explain(features, top_n=5) -> [(friendly_name, value, direction, size)]` (per-trial drivers: each input set to the typical train trial of `models/explain_reference.json`, change in log-odds of `gbm_uncalibrated`; max age and its flag move together; SHAP was rejected because it does not follow the GBM's native categorical splits), `model_features(model)` (the inputs a saved model was fitted on) and `to_model_frame(records, columns)`, the single dict/DataFrame -> model-input conversion used by training and the app. No sklearn-training or plotting imports | Adam | `app/`, `train.py`, `evaluate.py` |
| `game.py` | Logic of the guess-the-trial game: `load_test_trials` (test split with a phase label), `sample_pairs(trials, n, seed)` (one TERMINATED + one COMPLETED trial per pair, same `phase_label`, no repeats), `score_rows` (calls `predict.score_frame`, so the model gets only its own inputs), `model_pick` (higher score wins, a tie is a coin flip), `pairwise_accuracy` (ties count half) and `new_game` (pairs, display order and model picks for one game). No Streamlit | Raphael | `app/pages/5_Game.py` |
| `api_client.py` | Live ClinicalTrials.gov API v2 client for the app: `search_trials(query, status, page_size, phase, condition, sponsor_class)` (ongoing statuses incl. enrolling by invitation, **interventional studies only**: the model learned from those) and `get_trial(nct_id)` (never raise, errors come back as values: a plain `OFFLINE_MESSAGE` for users in `error`, the technical reason in `detail`; successful responses are cached 1 h through a private `_get_json` helper that raises on failure, so errors are never cached), `summarize(study)` for result cards (null lists tolerated). Offline fallback: `load_examples(path)` and `search_examples(query, phase, sponsor_class, page_size, path)` search the snapshot in `data/examples/ongoing_trials.json` with the same return shape (plus `saved_on`); `get_trial` falls back to it when the API fails. Imports streamlit only for caching. Full records go to `build_features` | Matteo | `app/pages/1_Find_a_Trial.py` |
| `save_examples.py` | `python src/save_examples.py` (online): fetches the first ongoing interventional trials for each example search of the Find page and writes their full records with the date to `data/examples/ongoing_trials.json` for the offline fallback. Uses `requests` directly and fails loudly | Claude | team, before a demo |
| `labels.py` | Plain-English names for API codes and data values (`label(kind, code)`: "DOUBLE" -> "Double blind", every spelling of "no phase" -> "No phase", gaps -> "Not stated") and for the model's input columns (`FEATURE_NAMES`, `feature_name(col)`, `feature_value(col, value)`: "has_dmc" -> "Has a data monitoring committee", 1 -> "Yes"). The only friendly-name map: How the model works page, driver charts and the what-if table all read it. Pure Python | Matteo / Adam | `app/`, `viz.py`, `predict.py` |
