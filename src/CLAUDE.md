# src/

Reusable Python for data fetching, feature building, model training and the ClinicalTrials.gov API client.
Not for: Streamlit code (`app/`), exploration (`notebooks/`), data files or saved models.
Must not import from `app/` or `notebooks/`. Rules in the root `CLAUDE.md` (label, leakage, date split) apply to
everything here.

Pipeline: `python src/fetch_data.py`, then `python src/build_dataset.py`, then `python src/train.py`
(tunes, fits, saves and evaluates the app models on feature set v1; `python src/train.py --features v2` trains the
condition-category GBM as `gbm_v2` next to them; `python src/evaluate.py` re-runs only the test evaluation).
`python src/build_dataset.py --backfill` adds new condition features to the existing parquet without raw pages.

| File | Contains / does | Produced by | Used by |
|---|---|---|---|
| `fetch_data.py` | Downloads all INTERVENTIONAL COMPLETED/TERMINATED studies from the API v2 into `data/raw/pages/` (resumable, retry/backoff, progress; projection also fetches `BriefTitle`, `LeadSponsorName` for display) | Simon | `build_dataset.py` |
| `features.py` | `build_features(study_json) -> dict`: the single feature function (design-time fields only) plus column lists. Absent lists count as 0; missing max age = 120 with `has_max_age` flag; no `start_year`/`fda_regulated_*` features. `condition_features(conditions)`: keyword multi-hot `cond_oncology` / `cardio` / `neuro` / `infectious` / `metabolic` / `psych` / `respiratory` / `healthy` + `n_condition_categories` (patterns in `CONDITION_KEYWORDS`, matched at word starts; `CONDITION_FEATURES` lists the columns). `study_from_design(design)` / `features_from_design(design)`: a design typed into a form -> minimal API record -> `build_features`, so the Check page uses the training rules instead of a copy. `FEATURE_COLUMNS` = every feature column (38); which ones a model uses is `FEATURE_SETS` in `train.py`. `DISPLAY_COLS` = app-only columns (title, conditions text, sponsor name, phase label), never model inputs | Simon / Adam | `build_dataset.py`, `train.py`, `app/` |
| `build_dataset.py` | Runs `build_features` over raw pages, applies label and 2008-2019 window, adds `split`, writes `data/processed/trials.parquet`, prints counts and the terminated rate per condition category. `--backfill` recomputes the condition features from the stored `conditions` text (split on `"; "`) instead | Simon | `train.py`, app visuals |
| `viz.py` | Explore-page helpers: `load_trials` (adds `start_year`, `outcome`, `eligibility_group`; turns codes into plain names through `labels.py`; missing values become "Not stated"), `filter_trials`, `rate_by`, `extremes` (highest/lowest group in words), `top_conditions`, Plotly figure builders (`rate_bar`, `rate_over_time`, `conditions_bar`, `eligibility_stats`) and `trials_table`. No colours or fonts: the figures take the app's Plotly template, which `app/ui.py` registers as the default (src must not import app). Pure pandas/Plotly, no Streamlit, no model | Adam / Matteo | `app/pages/3_Explore_Data.py` |
| `train.py` | Loads `trials.parquet` and checks label / window / split rules, builds the LR and GBM Pipelines, tunes each by 5-fold stratified CV on train (refit on PR-AUC), wraps the tuned GBM in `CalibratedClassifierCV(method='isotonic', cv=5)` fitted on train, picks each model's F1-max threshold on out-of-fold train predictions, saves `models/<name>.joblib` + `<name>_metrics.json`, `score_reference.npy` (OOF calibrated scores) and `explain_reference.json` (typical train trial), then calls `evaluate.evaluate_saved`. `FEATURE_SETS` = `v1` (29 original features, `APP_FEATURE_SET`) and `v2` (+ condition categories); `--features v2` trains only the GBM and saves it with a `_v2` suffix. `build_gbm_pipeline(drop=..., features=...)` serves the ablations | Adam | CLI, `evaluate.py` |
| `evaluate.py` | The only code that scores the test split: test ROC-AUC / PR-AUC / Brier, confusion matrix at the stored threshold, majority baseline, calibration before/after (JSON + plot), permutation importance CSV (a `_v2` run only replaces its own rows), LR coefficients, and the GBM feature ablations (refit on train without post-registration-editable features, scored once on test). Each model is fed its own input columns. Matplotlib is imported lazily, only for the plot | Adam / Dominic | `train.py`, CLI, `app/` |
| `predict.py` | `load_model(path='models/gbm.joblib')`, `score(features: dict) -> float` (**calibrated** P(TERMINATED)), `score_frame(records) -> array` (same, one call for a whole table; the How the model works page and the game use it), `percentile(prob) -> float` (0-100: share of training trials with a lower out-of-fold score), `reference_size()`, `explain(features, top_n=5) -> [(friendly_name, value, direction, size)]` (per-trial drivers: each input set to the typical train trial of `models/explain_reference.json`, change in log-odds of `gbm_uncalibrated`; max age and its flag move together; SHAP was rejected because it does not follow the GBM's native categorical splits), `model_features(model)` (the inputs a saved model was fitted on) and `to_model_frame(records, columns)`, the single dict/DataFrame -> model-input conversion used by training and the app. No sklearn-training or plotting imports | Adam | `app/`, `train.py`, `evaluate.py` |
| `game.py` | Logic of the guess-the-trial game: `load_test_trials` (test split with a phase label), `sample_pairs(trials, n, seed)` (one TERMINATED + one COMPLETED trial per pair, same `phase_label`, no repeats), `score_rows` (calls `predict.score_frame`, so the model gets only its own inputs), `model_pick` (higher score wins, a tie is a coin flip), `pairwise_accuracy` (ties count half) and `new_game` (pairs, display order and model picks for one game). No Streamlit | Raphael | `app/pages/5_Game.py` |
| `api_client.py` | Live ClinicalTrials.gov API v2 client for the app: `search_trials(query, status, page_size, phase, condition, sponsor_class)` (ongoing statuses incl. enrolling by invitation, **interventional studies only**: the model learned from those) and `get_trial(nct_id)` (never raise, errors come back as values; successful responses are cached 1 h through a private `_get_json` helper that raises on failure, so errors are never cached), `summarize(study)` for result cards. Imports streamlit only for caching. Full records go to `build_features` | Matteo | `app/pages/1_Find_a_Trial.py` |
| `labels.py` | Plain-English names for API codes and data values (`label(kind, code)`: "DOUBLE" -> "Double blind", every spelling of "no phase" -> "No phase", gaps -> "Not stated") and for the model's input columns (`FEATURE_NAMES`, `feature_name(col)`, `feature_value(col, value)`: "has_dmc" -> "Has a data monitoring committee", 1 -> "Yes"). The only friendly-name map: How the model works page, driver charts and the what-if table all read it. Pure Python | Matteo / Adam | `app/`, `viz.py`, `predict.py` |
